# Internationalization

Dates can follow the language the user is browsing in. Install
[`@nuxtjs/i18n`](https://i18n.nuxtjs.org) (v9 or v10) and Nuxt Luxon picks up its locale — no extra
configuration needed:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-luxon', '@nuxtjs/i18n'],
})
```

```vue
<template>
  <!-- en: July 12, 2024 at 12:23 PM UTC -->
  <!-- it: 12 luglio 2024 alle ore 12:23 UTC -->
  <p>{{ $luxon('2024-07-12T12:23:49.000Z', 'full') }}</p>
</template>
```

Switching language updates every formatted date, no page reload involved.

## How it works

When `@nuxtjs/i18n` is registered and no `output.locale` is configured, the module defaults
`output.locale` to the special value `'i18n'`.

A locale set to `'i18n'` is resolved on every format call, reading the active locale from
`@nuxtjs/i18n`. That has two consequences worth knowing:

- **It is reactive.** Dates formatted through `useLuxon(value)` are computed refs, so they re-render
  by themselves when the locale changes.
- **It is resolved on the server too.** The server renders the same locale as the client, so there is
  no hydration mismatch and no flash of the wrong language.

## Choosing a different locale

An explicit locale always wins, and is never overridden:

```ts
luxon: {
  output: {
    locale: 'en-US',
  },
}
```

The two can be mixed: keep a fixed default and ask for the user language only where it matters.

```ts
luxon: {
  output: {
    locale: 'en-US', // default for the whole app
  },
  templates: {
    userDate: {
      locale: 'i18n', // ...but this template follows the user language
      format: 'date_full',
    },
  },
}
```

```vue
<script setup>
const { $luxon } = useLuxon()

$luxon(date, 'userDate')
$luxon(date, { format: 'full', locale: 'i18n' })
</script>
```

The opposite works as well: follow the user language by default and pin a single call to a fixed
locale.

```vue
<script setup>
const { $luxon } = useLuxon()

$luxon(date, { format: 'iso' })                  // user language
$luxon(date, { format: 'full', locale: 'en-US' }) // always English
</script>
```

## Without `@nuxtjs/i18n`

`@nuxtjs/i18n` is an optional peer dependency: nothing is installed or loaded if you don't use it.

If `locale: 'i18n'` is used anyway — without the module registered — formatting falls back to the
[default locale](#default-locale) and a warning is logged in development.

## Default locale {#default-locale}

When no locale is set at all (the default), Luxon formats with the locale of the environment: the
browser one on the client, the one of the node process during SSR. Those two rarely match, so the
server-rendered output and the client one can differ and trigger a hydration mismatch.

The value `'client'` does the same thing: it is not a real language tag, so `Intl` ignores it and
falls back to the environment locale — exactly like any other unrecognized value.

```ts
luxon: {
  output: {
    locale: 'client', // browser locale on the client, node locale during SSR
  },
}
```

For a predictable output, prefer an explicit locale (`'en-US'`, `'it'`, …) or `'i18n'` to follow the
user language.
